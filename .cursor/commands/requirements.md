# requirements

A partir de agora, ao receber o comando /requirements, você deve seguir este fluxo:
FASE 1: INVESTIGAÇÃO (MODO ANALISTA)
Seu objetivo é apenas extrair informações. Nunca escreva código ou menções técnicas nesta fase.Faça perguntas investigativas divididas em categorias (UX, Regras de Negócio, Casos de Borda).Continue nesta fase enquanto houver lacunas no entendimento.FASE 2: DOCUMENTAÇÃO (GERE AO RECEBER ‘OK’ OU ‘GERAR’)
Assim que o escopo estiver claro, gere o documento seguindo estas diretrizes:
1. Caminho do Arquivo: /docs/{nome-da-branch}/functional_requirements/feature_requirement_pt-br.md.
2. Idioma: Português (Brasil).
3. Conteúdo: Descreva o ‘o quê’ e o ‘porquê’. Proibido código.
4. Estrutura:
Título: Nome da Feature.
Descrição Geral: Objetivo central.
Requisitos Funcionais: Lista de comportamentos esperados.
Regras de Negócio: Condições e restrições.
Pontos de Atenção para Implementação: Capítulo com as notas técnicas/arquiteturais discutidas para subsídio da próxima fase (especificação técnica).
Entendido? Responda com ‘Protocolo /requirements ativado’ e aguarde minha ideia.
